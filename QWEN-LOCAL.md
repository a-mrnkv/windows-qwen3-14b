# Локальная Qwen в Docker

Нужны драйвер NVIDIA, Docker Desktop в режиме Linux containers с WSL 2 backend,
Docker Compose 2.30.0+ и Git Bash или WSL с интеграцией Docker Desktop.
Оставьте около 15 ГБ свободного дискового пространства.

Запуск из этой папки:

```bash
bash start.sh         # Скачать модель при необходимости, запустить и открыть чат
bash start.sh serve  # Запустить API без чата
bash start.sh stop   # Остановить контейнер, сохранив модель
```

Модель: qwen3:14b. Контекст: 16384 токена. Выход из чата: /bye.
Первый запуск скачивает образ и модель через временный контейнер.
Рабочий контейнер имеет исходящий интернет через отдельную bridge-сеть.
Локальный API: http://127.0.0.1:11434.
Для OpenAI-совместимого клиента base URL: http://127.0.0.1:11434/v1.
Если клиент требует API key, используйте произвольное значение, например ollama;
это не средство аутентификации сервера. Выберите модель qwen3:14b.

OLLAMA_NO_CLOUD=1 отключает облачные модели и облачный поиск Ollama.
Это не универсальный переключатель всей телеметрии и не сетевой запрет отправок.
Проверяйте настройки телеметрии и облачных провайдеров IDE/расширения отдельно.
Модель сама не просматривает интернет: веб-поиск, чтение URL, редактирование
файлов и запуск команд предоставляет клиент или агент со своими разрешениями.

Папки Windows, домашняя директория, репозиторий и Docker socket в контейнер
не подключены. Он хранит модель в отдельном volume qwen-local-data. Дополнительные
Linux capabilities сброшены; повышение привилегий отключено. Сохраняется GPU-доступ.
Контейнер не получает доступ к файлам хоста через volume, однако обычная bridge-сеть
не запрещает обращения к доступным сервисам хоста или локальной сети. Docker —
изоляция процессов и файлов, не отдельная физическая система. Если IDE работает
на Windows, её команды выполняются с разрешениями IDE; контейнер Ollama их не изолирует.

Проверка после запуска:

```bash
curl --fail http://127.0.0.1:11434/api/tags
 docker exec qwen-local ollama ps
 docker network inspect qwen-local-network --format '{{.Internal}}'
```

После запроса в ollama ps ожидается 100% GPU; Internal должен быть false.
Если видеопамяти не хватает, уменьшите OLLAMA_CONTEXT_LENGTH до 4096 и перезапустите.
Контейнер остаётся запущен после /bye. Образ и модель автоматически не обновляются.
Если порт 11434 занят нативной Ollama, сначала остановите её.

## Мониторинг — Dozzle

Запускается и останавливается тем же start.sh вместе с Ollama.
Откройте http://127.0.0.1:8080: логи, состояние, CPU и RAM контейнеров проекта.
GPU-метрики этот интерфейс не предоставляет. Аналитика Dozzle отключена
(DOZZLE_NO_ANALYTICS=true), сеть мониторинга без исходящего интернета.
Dozzle не получает Docker socket напрямую: отдельный socket proxy разрешает
GET/HEAD к контейнерам, событиям и информации Docker. Изменяющие запросы запрещены,
shell и действия отключены. Порт proxy не опубликован и Ollama не подключена
к сети мониторинга. Сам proxy имеет доступ к Docker socket: суффикс :ro у socket
не запрещает операции Docker API; запрет записи обеспечивается конфигурацией proxy.
UI фильтрует контейнеры проекта; это фильтр отображения, не ограничение доступа
proxy к метаданным других контейнеров.

## OpenCode

Установленный OpenCode запускается командой bash start.sh opencode.
Скрипт сначала поднимает Ollama и мониторинг, затем запускает OpenCode в этой папке.
Настройки opencode.json выбирают ollama/qwen3:14b для основной и малой модели,
разрешают только провайдер ollama, отключают публикацию сессий и автообновление.
Конфигурация использует официальный формат OpenCode с @ai-sdk/openai-compatible.
Это не сетевой firewall и не универсальная гарантия отсутствия телеметрии.
OpenCode может скачивать пакет провайдера, LSP и зависимости инструментов.

Для другого проекта скопируйте opencode.json в его корень (не перезаписывайте
существующий без объединения), запустите здесь bash start.sh serve, затем
в папке проекта выполните opencode --model ollama/qwen3:14b.
OpenCode работает на хосте: его инструменты и команды не изолированы контейнером
Ollama. Полная изоляция агента потребует отдельного контейнера с подключением
только выбранной папки проекта. Контекст 16384 согласован с Ollama; длинные задачи
могут потребовать увеличения контекста с учётом доступной видеопамяти.

## Лимиты ресурсов

Ollama: до 16 ГБ RAM и CPU-квота 4 логических ядер. Dozzle: до 384 МБ RAM
и 0,5 CPU; socket proxy: до 128 МБ RAM и 0,5 CPU. Для каждого контейнера
memswap_limit равен mem_limit: использование swap контейнером запрещено.
Временный сервис скачивания также ограничен 16 ГБ RAM и 4 CPU.
Это максимумы, а не заранее выделенная память. Лимиты не распространяются
на VRAM, Docker Desktop/WSL в целом и OpenCode, работающий на Windows.
При исчерпании RAM контейнер может быть завершён OOM killer.
Применение: повторный запуск bash start.sh opencode или bash start.sh serve.

## Open WebUI и диагностика интерфейсов

Запуск: bash start.sh serve. Чат: http://127.0.0.1:3000;
мониторинг: http://127.0.0.1:8080. При первом входе создайте локальную учётную
запись администратора. Open WebUI подключён к http://ollama:11434 внутри Docker.
Данные пользователей и чаты сохраняются только в volume open-webui-data.
Образ slim предназначен для чата; обработка PDF, локальные embeddings и голос
потребуют дополнительных сервисов. Облачный OpenAI API отключён, offline mode
и отключение аналитики включены. WebUI ограничен 1 ГБ RAM и 1 CPU, без GPU.
Общий потолок RAM постоянных контейнеров теперь около 17,5 ГБ.
Dozzle дополнительно подключён к bridge-сети веб-интерфейса; Docker proxy
остаётся только во внутренней сети, без опубликованных портов.
Статус и последние логи: bash start.sh status. Скрипт проверяет внутреннюю
готовность WebUI и Dozzle и, при наличии curl, доступность веб-портов с хоста.

## Пересоздание при запуске

Каждый запуск chat, serve или opencode пересоздаёт все сервисные контейнеры
через docker compose up --force-recreate --remove-orphans. Docker volumes
не удаляются: скачанная модель, чаты WebUI и настройки Dozzle сохраняются.
Образы используются из локального кэша; это пересоздание контейнеров,
а не сборка образов или автоматическое обновление. Команды stop и status
не пересоздают сервисы.

Если OpenCode отсутствует в PATH, скрипт запускает официальный npm-пакет
opencode-ai через npx (или npx.cmd). Нужен Node.js LTS; первый запуск скачивает
пакет в npm-кэш без глобальной установки. Если установлены только Docker и Git,
установите Node.js LTS и откройте новый терминал. Браузерный чат не требует
OpenCode или Node.js: bash start.sh serve.

Локальные HTTP-проверки обходят HTTP_PROXY/HTTPS_PROXY/ALL_PROXY через curl
--noproxy "*", повторяются и показывают причину ошибки curl и привязки Docker
портов. Проверяется также API Ollama. Проверка из WSL относится к сетевому
пространству WSL и не всегда отражает доступ из браузера Windows.

Команда opencode повторно использует работающий стек: проверяет все четыре
контейнера и готовность Ollama, Dozzle и Open WebUI. Если они готовы, скачивание
и пересоздание пропускаются. Если стек не готов, выполняется обычное пересоздание.
Для применения изменений compose.yaml к работающему стеку используйте
bash start.sh serve. Эта проверка относится к сервисам Docker, а не к истории
или процессам сессий самого OpenCode: каждый вызов открывает новый клиент.

## Стиль ответов

Modelfile создаёт модель qwen3-local на основе скачанной qwen3:14b с системной
инструкцией для прямых ответов без ненужных нравоучений. Веса повторно не скачиваются.
Скрипт применяет Modelfile при запуске, в том числе при повторном использовании
сервисов. OpenCode и терминальный чат используют qwen3-local; в Open WebUI она
задана моделью по умолчанию. В существующем чате выберите qwen3-local вручную.
Это настройка стиля, а не полное отключение ограничений модели.
